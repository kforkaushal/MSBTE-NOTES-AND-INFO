## 4. Audit: what is missing or broken

### P0: fix first (indexing and consistency)

#### P0-1. Conflicting canonical and URL variants **[Safe] · Effort M**
**Evidence**
- `/start` declares its canonical as `/start.html`, yet the whole site links to `/start`. Search Console classes `/start` as "Alternate page with proper canonical tag".
- `/Notes/` (capital N) redirects to `/notes/`. Your home page links to both `/Notes/` and `/notes/`.
- Search Console shows the same page type in three forms: `/pyq/315339-mobile-and-wireless-communication.html`, `/pyq/315313-theory-of-structures`, `/pyq/312313-manufacturing-technology/`.
- Capitalised paths also earn impressions: `/Blog/dpharm-exit-exam-cancelled-2026.html`, `/Branches/elective-315374-power-plant-engineering.html`.
- `/scheme/i-scheme.html` and `/scheme/k-scheme.html` are indexed with `.html`, while your HTML sitemap links `/scheme/i-scheme`.

**Fix**
1. Pick one rule: lowercase, no `.html`, no trailing slash except hubs that already use it (`/notes/`, `/pyq/`, `/model-answer/`, `/blog/`).
2. Make every `<link rel="canonical">` self-referencing and in that format. For `/start`, the canonical must be `https://msbtenotes-info.netlify.app/start`.
3. Update internal links to that format (find `/Notes/`, `.html`, and `/#notes`).
4. In Netlify, confirm "Pretty URLs" is on so `.html` versions 301 to the clean URL. Verify with `curl -sI` (Section 12).
5. Do **not** add `/Notes/* → /notes/*` redirect rules. Some Netlify redirect matching is case-insensitive and a lowercase-to-lowercase rule can loop. Fix links and canonicals instead.

#### P0-2. Sitemap setup is inconsistent **[Safe] · Effort M**
**Evidence**
- Search Console shows the home page was discovered through three sitemaps: `/SITEMAP.XML` (uppercase), `/rss.xml` and one more. `/pyq/` and `/notes/` show `/sitemap.xml`.
- Three different "sitemap" URLs exist: `/sitemap` (HTML page), `/sitemap.html` (what Google crawls), `/sitemap.xml` (footer link on `/pyq/`). The HTML sitemap says "last updated August 2026" and claims 400+ pages and 67 posts.

**Fix**
1. Keep one XML sitemap index at `/sitemap.xml` (lowercase) and remove `/SITEMAP.XML` in Search Console.
2. Split it by section: `sitemap-blog.xml`, `sitemap-notes.xml`, `sitemap-pyq.xml`, `sitemap-model-answer.xml`, `sitemap-branches.xml`, `sitemap-colleges.xml`.
3. List only canonical, 200-status, indexable URLs. Include accurate `<lastmod>` (only change it when the page content changes).
4. Keep `/rss.xml` as a feed only, not a sitemap.
5. Footer "Sitemap" link: point to the HTML sitemap everywhere (`/sitemap`) and add `<link rel="sitemap" href="/sitemap.xml">` in `<head>`.
6. Add `Sitemap: https://msbtenotes-info.netlify.app/sitemap.xml` to `robots.txt` (template in 6.2).

#### P0-3. Semester pages may not be indexed **[Safe] · Effort M**
**Evidence:** URL Inspection for `/branches/computer-semester-4` returned "URL is unknown to Google". Your home page links to 42 semester pages (7 branches × 6 semesters) and the HTML sitemap claims 180+ branch pages. Only one was checked, and Google may know it under another variant, but this is the exact page type that should capture "computer engineering sem 4 msbte notes" searches.

**Fix**
1. In Search Console → Pages, filter by `/branches/` and see how many are "Discovered/Crawled – currently not indexed" or missing.
2. Make sure every branch/semester page is in the sitemap (P0-2) and linked from its branch hub and from the matching subject pages.
3. Each branch-semester page needs a unique title, description and one paragraph of intro text (Section 5.1). Thin, near-identical pages are the usual reason Google skips them.

#### P0-4. Operating System code mismatch **[Safe for meta/schema, Visible for H1] · Effort S**
**Evidence**
- `/notes/osy-k-scheme-notes` is titled "OSY (314319) Operating System …", its meta description says "4th Sem", and the homepage card says "314319 … 4th Semester". The same page's body text calls it a "fifth-semester subject".
- Your own `/pyq/` listing shows **Operating System = 315319, Sem 5** and **314319 = Information Security (IT), Sem 4**. The page also links to `/notes/315319-operating-system`.
- People search with the code: your Search Console shows "osy model answer paper 315319" and "315339 model answer"; Campusify's meta keywords use "MSBTE OSY 315319".

**Fix:** Confirm the code and semester against the official MSBTE K-scheme PDF, then correct title, meta description, `og:title`, schema and (optionally) the H1 so they all say the same code. Re-check the other 7 notes pages that carry a code in the title (DBMS 313302, DSU 313301, DTE 313303, OOP 313304, JPR 314317, DCN 314318, MIC 314321) against the same PDF. Your `/pyq/` list agrees with all of those.

#### P0-5. Navigation links to anchors, not pages **[Safe] · Effort S**
**Evidence:** On the OSY notes page, the nav item "Notes" and the breadcrumb "Notes" link to `/#notes`; "Blog" on the home page links to `/#blogs`.
**Fix:** Point them at `/notes/` and `/blog/`. Real URLs pass link signals and appear in breadcrumbs; fragment links do not.
