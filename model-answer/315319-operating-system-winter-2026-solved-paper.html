Q.1 b)

Define Process and PCB (Process Control Block).

1. Process: A program in execution is called a process. While a program is a passive entity stored on disk (e.g. code.c or an executable app.exe), a process is an active entity loaded into main memory containing the program counter, stack, data section, and heap.
2. PCB (Process Control Block): A data structure maintained by the Operating System for each process that stores all metadata needed to manage, schedule, and context-switch that process. Key fields include: Process ID (PID), Process State, Program Counter (PC), CPU Registers, Scheduling Priority, Memory Management Limits, and I/O Status. It is also termed a Task Control Block.

Q.1 c)

Define CPU-bound and I/O-bound programs.

  • CPU-bound Program: A program that spends the majority of its execution time performing computational processing. It exhibits long CPU bursts and few I/O operations.
    Examples: Scientific simulations, 3D video rendering, heavy matrix multiplication, cryptographic hashing.
  • I/O-bound Program: A program that spends the majority of its time waiting for input/output operations to complete. It exhibits short CPU bursts interspersed with frequent, prolonged I/O requests.
    Examples: Text editors, file copy utilities, database queries, interactive web browsers.

Q.1 d)

Define Memory Compaction and Fragmentation.

1. Compaction: A memory management technique of rearranging allocated memory partitions in physical RAM so that all scattered free memory holes are consolidated into one single, contiguous free block. Compaction eliminates external fragmentation, but is feasible only when relocation is dynamic at execution time.
2. Fragmentation: Inefficient memory utilization where storage space is wasted and cannot be assigned to processes:
  • Internal Fragmentation: Unused space inside an allocated memory block (e.g., allocating a 100 KB partition to an 80 KB process wastes 20 KB internally).
  • External Fragmentation: Total free memory across RAM is adequate to satisfy a request, but storage is non-contiguous, preventing allocation.

Q.2 a)

Explain Time Sharing Operating System with its features and architecture.

Definition: A Time-Sharing (Multitasking) Operating System is an extension of multiprogramming in which the CPU executes multiple jobs by rapidly switching among them using small allotted time intervals called time slices or time quanta (typically 10 to 100 ms). The switching happens so quickly that each user interacting via a terminal experiences a dedicated, responsive machine.
Fig 2.1: Time Sharing Operating System Architecture & Time Quantum Allocation
Key Features of Time-Sharing OS (Write any 6):
  1. Time Quantum / Slicing: CPU provides each process an equal fixed duration of time. If a process does not complete within its quantum, it is preempted and returned to the ready queue.
  2. Rapid Context Switching: CPU switches from one active terminal process to another seamlessly without human notice.
  3. Interactive Short Response Time: Response time is kept extremely low (often < 1 second), making it ideal for interactive terminal tasks.
  4. Multi-User Concurrency: Multiple users can access computational resources and run simultaneous programs on one central server.
  5. Round-Robin Scheduling: Implements a circular FIFO queue to guarantee fair CPU sharing without job starvation.
  6. Memory Swapping: Swaps inactive or waiting processes to secondary disk storage (virtual memory) to accommodate active processes in main memory.
  7. System Resource Protection: Memory segments and file directories are strictly segregated and protected among concurrent users.
Real-world Examples: UNIX, Linux, Multics, Windows Server terminal services.
Key Limitation: High CPU switching overhead and complexity of multi-tenant security/integrity.

Q.2 b)

Draw and explain the Process State Transition Diagram.

Fig 2.2: Standard 5-State Process Model with Transitions
Explanation of 5 Fundamental Process States:
  • 1. NEW: The process is initially being created by the OS and its PCB is being generated; it has not yet entered main memory.
  • 2. READY: The process has been loaded into main RAM and is positioned in the ready queue, waiting for the short-term CPU scheduler to assign CPU time.
  • 3. RUNNING: Instructions of the process are actively being executed by the CPU core (only one process per CPU core can run at a time).
  • 4. WAITING / BLOCKED: The process cannot execute because it is waiting for an external event to occur, such as I/O transfer completion, child process exit, or user input.
  • 5. TERMINATED: The process has concluded execution or was aborted; the OS deallocates its memory partition and cleans up its PCB.
Process State Transitions:
Admit: Long-term scheduler moves process from NEW → READY.
Dispatch: Short-term scheduler assigns CPU from READY → RUNNING.
Interrupt: Timer interrupt or higher priority arrival shifts RUNNING → READY.
Event Wait: Process initiates an I/O request and shifts RUNNING → WAITING.
Event Completion: I/O finishes or event occurs; process moves WAITING → READY.
Exit: Process ends operations and transitions RUNNING → TERMINATED.

Important Exam Rule: Transitions from Waiting → Running or Ready → Waiting are physically impossible in standard OS design.

Q.2 c)

Explain Fixed-Size (Static) Memory Partitioning with a neat diagram.

Concept: In Fixed-Size (Static) Partitioning, system main memory is divided at system configuration time into a fixed number of non-overlapping partitions of predetermined fixed sizes (either equal or unequal). Each partition accommodates exactly one process at a time; therefore, the maximum degree of multiprogramming is strictly bounded by the number of partitions.
Fig 2.3: Fixed-Size Static Memory Partitioning with Internal Fragmentation
Operational Working:
  1. The OS maintains a Partition Table storing the base starting address, partition size, and current allocation status (Free/Allocated) for all blocks.
  2. When a new process arrives, the OS scans the partition table to select an available free partition that is equal to or larger than the process footprint.
  3. Protection is guaranteed via Base and Limit registers to prohibit a process from accessing adjacent partitions or the operating system memory.
  4. Upon process termination, the partition is reset to "Free" status for subsequent processes.
Advantages:
  • Extremely simple to manage and implement.
  • Negligible OS management overhead.
  • Requires minimal hardware address-translation support.
Disadvantages:
  • Internal Fragmentation: Space left inside an allocated partition is wasted (e.g., 20 KB in Part 1 and 80 KB in Part 3 above).
  • Process Size Limitation: A process exceeding the largest partition cannot be loaded without overlays.
  • Fixed multiprogramming degree regardless of small program sizes.

Q.3 a)

Define Deadlock and explain any two necessary conditions for a deadlock to occur.

Definition of Deadlock: A deadlock is a condition in a multiprogramming system where a set of processes are permanently blocked because each process holds at least one shared resource while waiting to acquire another resource currently held by another process in the same set, resulting in an indefinite freeze.
Fig 3.1: Circular Wait Dependency Cycle in Resource Allocation Graph (Deadlock Condition)
Four Necessary (Coffman) Conditions for Deadlock:

Deadlock can arise if and only if all four conditions hold simultaneously: (1) Mutual Exclusion, (2) Hold and Wait, (3) No Preemption, (4) Circular Wait.

1. Mutual Exclusion: At least one resource must be held in a non-shareable mode — only one process can use the resource at any given moment. If another process requests that non-shareable resource, the requesting process must wait until it is formally released.
Example: A physical printer or tape drive can execute only one print job at a time. Read-only shared files do not cause mutual exclusion.
2. Hold and Wait: A process must be actively holding at least one resource while waiting to acquire additional resources that are currently allocated to and held by other operating processes.
Prevention: OS can require a process to request and be allocated all necessary resources upfront before starting execution.
Summary of other two conditions:
• No Preemption: Allocated resources cannot be forcibly seized; they are released only voluntarily by the holding process.
• Circular Wait: A closed chain of processes {P0, P1, ..., Pn} exists such that P0 waits for a resource held by P1, and Pn waits for P0.

Q.3 b)

Explain CPU Scheduling Criteria with relevant formulas.

To compare and evaluate different CPU scheduling algorithms, operating system designers rely on the following standard performance criteria:

1. CPU Utilization (Maximize): Percentage of time the CPU core is executing useful user/kernel tasks rather than idling.
Utilization = (CPU Busy Time / Total Time) × 100%
2. Throughput (Maximize): Number of completed processes per unit of elapsed time (e.g., 50 processes/minute).
Throughput = Total Completed Processes / Total Time
3. Turnaround Time (TAT) (Minimize): Interval from the instant a process is submitted to its complete execution finish.
TAT = Completion Time (CT) − Arrival Time (AT)
4. Waiting Time (WT) (Minimize): Cumulative duration spent by a process sitting idle in the ready queue awaiting CPU time.
WT = Turnaround Time (TAT) − Burst Time (BT)
5. Response Time (Minimize): Time elapsed from initial process submission until the very first CPU response/output is produced. Crucial in interactive and time-sharing operating environments.
Response Time = Time of First CPU Allocation − Arrival Time (AT)

Additional criteria: Fairness (equal opportunity for all tasks) and Starvation Avoidance (mitigated via Aging).

Q.3 c)

Explain Bitmap and Linked List Free-Space Management techniques for disk storage.

1. Bitmap (Bit Vector) Method:

The disk free-space list is implemented as a bit map vector where each disk block is represented by a single bit:

bit = 0 → Block is Free  |  bit = 1 → Block is Allocated
Block:01234567
Bit:11001001
State:AllocAllocFreeFreeAllocFreeFreeAlloc
Advantage: Simple and extremely fast in finding the first free block or continuous runs of free blocks via hardware word bit-scans.
Disadvantage: For large terabyte disks, the bitmap becomes too big to hold entirely in main RAM.
2. Linked List (Free List) Method:

All unallocated free disk blocks are linked together in a linked list structure. Each free block contains a pointer referencing the next available free block. The OS preserves a pointer to the first free block (Head Pointer) in memory.

[Head: Blk 2] → [Blk 2 | ptr=3] → [Blk 3 | ptr=5] → [Blk 5 | ptr=6] → [Blk 6 | ptr=NULL]
Advantage: No disk storage space is wasted on tables because pointers reside directly within the unallocated blocks themselves.
Disadvantage: Traversal is slow (requires sequential disk reads); cannot find contiguous blocks efficiently.

Q.3 d)

Explain Two-Level Directory and Tree-Structured Directory with diagrams.

1. Two-Level Directory Structure:

To prevent name collisions between different users in multi-user environments, a Master File Directory (MFD) is created at the top level. The MFD is indexed by user name/ID, and each entry points to a distinct User File Directory (UFD). Each user operates within their own isolated UFD.

[MFD (Master Directory)]
↓
└── [User 1 UFD] → [fileA, fileB, test.c]
└── [User 2 UFD] → [fileA (same name allowed!), proj.docx]
└── [User 3 UFD] → [data.csv, lab.py]

Pros/Cons: Solves name conflicts among users; however, users cannot collaborate easily, and sub-directories cannot be created within a user account.

2. Tree-Structured Directory:

The standard hierarchical directory structure in modern operating systems (Windows, Linux). An arbitrary depth of directory tree extends downwards from a single Root Directory (/ or C:\). Directories can contain regular files as well as nested sub-directories.

Root ( / )
└── /bin → [ls, cp, rm]
└── /home
    └── /student → [/notes, /assignments → [osy.pdf]]
└── /etc → [passwd, hosts]

Pros: Full flexible grouping, powerful search, supports both Absolute Paths (/home/student/notes) and Relative Paths (./notes).

Q.4 c)

Differentiate between Paging and Segmentation memory management schemes with diagrams.

Paging Concept: Logical memory is divided into fixed-size blocks called Pages. Physical memory is divided into blocks of the exact same size called Frames. A Page Table maps logical page number (p) to frame number (f).
Logical Address: [Page p | Offset d]
Physical Address = (Frame f × Page_Size) + d
Segmentation Concept: Logical memory is divided into variable-size logical modules called Segments (e.g. main routine, stack, symbol table). A Segment Table maps segment number (s) using Base and Limit.
Logical Address: [Segment s | Offset d]
Check: if (d < Limit) Physical = Base + d;
Parameter Paging Segmentation
1. Block Size Fixed block sizes (typically 4 KB). Variable sizes depending on logical module length.
2. View / Division Managed transparently by OS/hardware (invisible to user). Programmer/compiler oriented logical division (visible).
3. Mapping Table Page Table stores Frame numbers. Segment Table stores Segment Base and Limit addresses.
4. Fragmentation Suffers only Internal Fragmentation (last page). Suffers External Fragmentation (needs compaction).
5. Protection / Sharing Difficult to logically protect parts of code. Very easy (e.g., mark code segment read-only).

Q.4 e)

Define Context Switching. Describe the stepwise switching procedure with a neat diagram.

Definition: Context Switching is the administrative procedure performed by the OS kernel of saving the state (context) of the currently running process in its PCB and loading the saved state of another process from its respective PCB, thereby allowing a CPU core to switch execution among multiple tasks. It constitutes pure computational overhead since the CPU performs zero user computation during the switch.
Fig 4.2: CPU Context Switch Sequence Between Process 1 and Process 2
Step-by-Step Procedure of Context Switching:
  1. An external timer interrupt, hardware trap, or system call occurs, transferring CPU control from user mode into kernel mode.
  2. The OS dispatcher suspends Process P1 and saves its current hardware state (Program Counter, CPU registers, stack pointer, PSW) into PCB1.
  3. The OS updates the process status of P1 from RUNNING to READY (or WAITING) and repositions it in the appropriate kernel queue.
  4. The CPU scheduler algorithm selects the next scheduled process (Process P2) from the ready queue.
  5. The OS dispatcher accesses PCB2, restores its memory mapping tables (page directory, TLB, cache flush), and reloads saved register contents.
  6. The process state of P2 is updated from READY to RUNNING.
  7. The program counter (PC) from PCB2 is loaded into the CPU hardware register, and Process P2 resumes active instruction execution.

3 Sequential Access Superb & fastest; minimum disk head movement. Good; sequentially follows next-pointers. Good; reads pointers sequentially from index table.
4 Direct (Random) Access Very easy and fast: Block i = Start + i. Extremely slow / impractical; requires traversing i disk reads. Fast & direct: Index block directly yields block i.
5 Fragmentation Severe External Fragmentation (demands disk compaction). Zero external fragmentation. Zero external fragmentation; suffers table overhead.

Q.6 b)

Given memory partitions with free holes in order: 12 KB, 19 KB, 7 KB. Show how a process request of 6 KB is allocated using First Fit, Best Fit, and Worst Fit algorithms.

Given Parameters: Process Request = 6 KB • Free Holes in memory list: H1 = 12 KB, H2 = 19 KB, H3 = 7 KB
Fig 6.3: Memory Partition Allocation for 6 KB Process Request
1. First Fit Algorithm (2 Marks): Allocates the very first free hole from the beginning of memory that is large enough to satisfy the request (≥ 6 KB).
• Scans H1 (12 KB): Since 12 KB ≥ 6 KB → Allocated in H1.
• Leftover in H1: 12 KB − 6 KB = 6 KB.
• Resulting Free Hole List: 6 KB, 19 KB, 7 KB.
Assessment: Fastest search since allocation halts at the first valid hole.
2. Best Fit Algorithm (2 Marks): Searches the entire memory list and allocates the smallest hole that is large enough to minimize leftover fragment.
• Available candidates: 12 KB, 19 KB, 7 KB. Smallest suitable hole is H3 (7 KB).
• Leftover in H3: 7 KB − 6 KB = 1 KB.
• Resulting Free Hole List: 12 KB, 19 KB, 1 KB.
Assessment: Produces highest memory fit, but creates a tiny, virtually unusable 1 KB hole (severe external fragmentation).
3. Worst Fit Algorithm (2 Marks): Searches the entire memory list and allocates the largest available free hole so that the leftover remains large enough to house future tasks.
• Largest hole in memory is H2 (19 KB) → Allocated in H2.
• Leftover in H2: 19 KB − 6 KB = 13 KB.
• Resulting Free Hole List: 12 KB, 13 KB, 7 KB.
Assessment: Prevents tiny fragment generation; however, it breaks apart the system's largest continuous free block.

Q.6 c)

State the advantages of multithreading and differentiate between a Process and a Thread.

Thread Definition: A thread (lightweight process) is the smallest basic execution unit of CPU utilization. It comprises its own Thread ID, Program Counter (PC), Register set, and private Stack, while sharing the code section, data section, and OS resources (such as open files) with peer threads of the same parent process.
Advantages of Multithreading (Write any 6):
  1. Responsiveness: Allows an interactive application to remain responsive to user input even if a portion of the program is blocked or performing an extensive computation (e.g. browsing the web in one tab while downloading a file in another).
  2. Resource Sharing: Threads automatically share memory address space and open file descriptors of their enclosing process, eliminating the need for complex IPC (Inter-Process Communication).
  3. Economy (Low Overhead): Allocating memory and creating a thread is significantly cheaper in memory and CPU time than creating a heavyweight process (thread creation is ~30× faster; context switching is ~5× faster).
  4. Scalability on Multicore CPUs: Multiple threads of a single process can execute in true hardware parallelism across multiple distinct CPU cores. A single-threaded process is bounded to a single core.
  5. Higher CPU Utilization & Throughput: When one thread blocks waiting for disk or network I/O, other threads continue CPU execution, preventing processor idle time.
  6. Simplified Software Modularization: Complex background operations (such as auto-saving and spell-checking in a word processor) are partitioned naturally as dedicated worker threads.
Process vs Thread Comparison:
Parameter Process (Heavyweight) Thread (Lightweight)
1. Definition An independent program in execution with separate dedicated system resources. A lightweight unit of execution that runs within the context of a parent process.
2. Address Space & Memory Each process has its own isolated memory address space, stack, heap, and data section. Shares code, data, heap, and global variables with peer threads; only stack and registers are private.
3. Creation & Switch Time High overhead; requires complete page directory allocation and PCB duplication. Low overhead; very fast creation and lightweight context switching.
4. Inter-Task Communication Requires operating system IPC mechanisms (pipes, message queues, sockets, shared memory). Direct communication via shared process variables and memory pointers.
5. Fault Isolation Crash of one process does not affect other running processes (isolated). A memory fault or crash in one thread can terminate the entire host process.
